# LUNAVI — Project audit (14 Nov 2026)

Audited input: `Archive.zip` uploaded 14 Nov 2026 (the developer's Xcode project folder).

## 1. What exists

| Area | Content |
|---|---|
| App | SwiftUI iPadOS app, Swift 6, 86 Swift files; `@Observable @MainActor` stores; Swift Charts; PDFKit |
| Screens | Lunar south-pole map (real LOLA-derived basemap), site inspector, mission parameters (date/time, duration, delay), visibility timeline, shadow/horizon view, site comparison, Earth communication windows, solar-power estimate, terrain characteristics, Mission Rescue, PDF mission report, data & method screen, 12-step tutorial |
| Data in the app | Real computed datasets (schema 3): 17 Nov – 1 Dec 2026 and 1 Dec 2026 – 1 Mar 2027, 3 PGDA 78 sites; clearly labelled demo dataset as offline fallback |
| Science pipeline | Python `ScienceService`: SPICE (spiceypy, DE421, MOON_ME), LOLA PGDA 78 (5 m) + PGDA 90 (20 m) horizons, interval export, kernel-coverage checks, terrain metrics, acceptance + validation tooling |
| Tests | 105 Python tests; 97 Swift unit tests; 1 UI test (full Mission Rescue journey); real-data acceptance scenarios A–E |
| Docs | README, METHODOLOGY, VALIDATION, DATE_RANGES, ATTRIBUTION, validation results |

The archive is identical to the working repository except: the developer's own app icon
(`LUNAVI_AppIcon_1024.png`, now adopted), the real computed datasets (now committed), and local-only folders that
are deliberately **not** in the source ZIP (`.venv` 298 MB, `data` 118 MB, `kernels` 18 MB, `out` 6 MB,
`python-3.12.10-macos11.pkg` 44 MB) — all re-creatable with `scripts/build_real_data.sh`.

| Feature | Status |

is marked as demonstration; anything outside computed coverage shows **Unknown**.
